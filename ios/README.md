# 豆奶签到 iOS 版

**作者目前正在日常使用 iOS 版，推荐使用。** 后续会优先维护 iOS，功能更新和问题修复会更及时；后台自动签到仍受下文所述的系统限制。

iOS 工程使用 SwiftUI、WKWebView、Vision 和 BackgroundTasks，不依赖第三方软件包。最低系统版本为 iOS 16。

## 当前功能

- 在应用内打开网站原页面，完成邮箱、密码和验证码登录。
- 将登录 Cookie 保存在本机 Keychain，不保存登录密码。
- 手动执行一次签到，并在请求后接收服务端更新的 Cookie。
- 首页最上方显示当天签到状态、最近结果和北京时间更新时间；今日已成功时，再次手动签到需要确认。保存配置不覆盖签到结果。
- 设置每天的北京时间，通过系统后台刷新任务尝试自动签到。
- 验证码无法识别时换图，服务端明确拒绝验证码时重新获取票据后补试；同一任务最多提交两次，受后台时间预算限制。
- PNG 使用多版本灰度/自适应二值化去重，至少两个不同版本得出唯一最高共识才提交；Vision 与 Android 的 ONNX 识别引擎不同，不保证相同识别率。
- 可复制和分享的运行日志，记录后台计划、权限状态、实际唤醒、请求阶段、识别共识、重试和系统超时。
- 发送签到成功、失败或需要重新登录的 Bark 通知。
- 邮件通知：支持 SMTP 465 TLS 和 587 STARTTLS、独立收件邮箱及测试发送；收件邮箱留空时发送给自己。
- 退出账号并清除 Cookie 和 WebKit 网站数据。

低电量 Bark 当前只在 Android 版提供。

在“邮件通知”中开启发送签到结果邮件，填写发件邮箱、SMTP 主机、端口和邮箱服务提供的授权码，点“保存邮件设置”后使用“发送测试邮件”验证。发件邮箱同时作为 SMTP 登录账号；SMTP 需支持 AUTH LOGIN。授权码保存在本机 Keychain，退出站点账号时保留通知配置。Bark 与邮件并行发送，通知失败会显示在最近结果中，不会把签到成功改为签到失败。

邮件连接验证服务器证书及主机名，587 必须成功升级到 TLS 后才发送登录凭据。SMTP 会话最多等待约 25 秒，系统终止后台任务仍可能提前中断发送。不会自动重发邮件；若提交后连接中断且未获得确认，会提示“发送状态未知”，请检查收件箱。服务器接收不代表邮件已经到达收件箱。

## 构建和安装

1. 在 Mac 上安装 Xcode 16 或更高版本。
2. 用 Xcode 打开 `ios/DounaiCheckin.xcodeproj`。
3. 在 Signing & Capabilities 中选中自己的 Apple 账号。
4. 连接 iPhone，选择这台手机后点运行。

用免费 Apple 账号也可以给自己的手机安装，但过一段时间后可能需要重新安装。仓库目前不提供可直接下载的 IPA。

## 后台执行限制

iOS 的后台刷新由系统根据使用习惯、电量和网络状况统一调度。应用提交的时间只表示最早执行时间，系统可能延后运行，也可能在长期不打开应用时减少后台机会。手机关机、断网或应用被系统限制后台刷新时无法保证当天签到。

首次启用自动签到后，请正常返回桌面并保留系统的“后台 App 刷新”权限。每次打开应用或进入后台时，应用会更新下一次后台任务请求。

从多任务界面向上划掉应用通常会阻止后台启动，需要手动重新打开。回到桌面、锁屏或进程被系统回收后，系统仍可能投递后台刷新，但不保证当天运行或准点执行。开发版签名过期也会导致无法运行。

v1.0.2 会保留同一设置下更早的待执行请求；当日任务逾期且没有成功或终止失败记录时，申请尽早补跑。手动或自动成功均按北京时间记录，自动任务同日不重复提交；失败不会记为成功。提交前临时网络错误在时间允许时立即补试一次，后台仍失败则申请约 5、10、15 分钟后的机会（不是准时重试保证），最多三次；提交后状态不明时不自动重试。其他终止失败当天需要手动重试，或重新保存自动签到设置申请新的机会。

签到请求阶段使用约 20 秒后台预算，整个后台处理申请约 25 秒后主动取消，系统也可能更早终止。应用被系统挂起或被调试器暂停期间，定时器无法执行，恢复运行后才处理超时；这不是保证在 25 秒墙钟时间内完成的系统级限制。系统超时和主动超时共用一次完成保护；识别和通知收到取消信号后停止继续处理，通知慢不会清除已确认的签到成功记录。应用关闭自动签到或退出账号后，残留任务也会跳过。

首页顶部“签到状态 → 运行日志”可刷新、复制或分享最近最多约 512 KiB 的诊断记录。日志不包含站点地址、Cookie、密码、Bark Key、邮箱地址、SMTP 授权码或服务端原文；应用被强退期间无法写日志。系统待执行请求通过异步查询采样，不能据此确定强退来源。

## 登录与隐私

登录全过程使用网站原页面，应用不提供独立的邮箱、密码或验证码输入接口。Cookie、Bark Key 和 SMTP 授权码保存在 Keychain；普通设置和最近结果保存在应用的 UserDefaults。退出账号会关闭自动签到并清除本机登录数据。

## 邮件流程回归测试

在已安装 Xcode 或命令行工具的 Mac 上运行（无需邮箱凭据，不会发出邮件）：

```sh
xcrun swiftc -swift-version 5 -parse-as-library DounaiCheckin/EmailClient.swift Tests/EmailClientTests.swift -o /tmp/dounai-email-tests
/tmp/dounai-email-tests
```

签到流程回归测试从仓库根目录运行，不访问真实站点、不执行账号签到：

```sh
xcrun swiftc -swift-version 5 -parse-as-library \
  ios/DounaiCheckin/{CheckInPolicy,DiagnosticLog,CaptchaSolver,CheckInClient,AppSettings,KeychainStore,BarkClient,EmailClient}.swift \
  ios/Tests/CheckInTests.swift -o /tmp/dounai-checkin-tests
/tmp/dounai-checkin-tests
```

已知局限：Android 的细横线 PNG 样本在 macOS Vision 回归中仍被保守拒识；测试要求它识别正确或停止提交，不将拒识计为识别成功。实际 iPhone 的识别率需要继续用真机样本验证。调度单元测试及真机计划登记验证不等于自然后台唤醒测试，后者需要在无调试器连接时持续观察运行日志。

### 2026-10-17 真机受控验证

iPhone 14 / iOS 18.6.2：通过开发调试器模拟后台入口，并临时申请 UIKit 后台执行额度后，真实验证码取得两个不同版本的一致答案，签到服务端返回成功，Bark 成功；任务切到后台后继续执行，约 12 秒完成。邮件通知未开启，本轮未发送邮件。

模拟系统提前终止时，只记录一次失败完成；下一次每日请求保留。验证过程中补充了启动前终止保护，并将下一次计划的登记移至工作任务创建之前。同日再次模拟触发时，直接跳过签到，不再提交或发通知。

这些受控测试不证明系统会自然按时唤醒，也不证明手动从多任务界面划掉应用后仍可自动启动。所有模拟仅由开发调试器调用，应用源码不包含模拟接口。

另一次短时自然调度观察中，临时登记一分钟后的请求、断开调试器并锁屏；约三分钟观察窗口内未出现自然后台入口记录，期间末尾曾短暂打开应用。因此本轮不将自然唤醒标为通过，也不将其判为失效。观察结束后已重新登记原每日计划；自然唤醒仍需无调试器的更长时间观察。
