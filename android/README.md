# 豆奶签到 Android 版

Android 是当前推荐版本，已经在真实手机上完成网页登录、亮屏手动签到、黑屏签到和后台任务测试。

手机应用在应用内登录站点，保存当前站点的 Cookie，然后每天在北京时间指定时间提交一次签到。签到会先读取页面所需的校验信息，再加载并识别验证码，等待 4–7 秒后按网站当前流程提交。PNG 验证码需要至少两个不同预处理版本得出相同答案；识别无法确认或服务端明确返回验证码错误时会立即换一张再试，每个任务最多补试一次。开启自动签到后还会约每 3 小时刷新登录态并接收服务端更新的 Cookie。后台签到支持 SVG 算式验证码与 PNG 图片 OCR，签到成功或失败可发送 Bark 和邮件通知；服务端明确判定登录失效时会发一次 Bark 提醒。

使用步骤：安装 APK；在首页输入豆奶站点的 HTTPS 根地址并打开签到页。点击网页密码框或顶部“输入密码”，在系统输入框中完整输入后点“填入网页”；密码只写回当前网页且不会保存，顶部会显示填入的字符数。邮箱、算式验证码和登录按钮仍使用网站原页面，验证码不会离开网站流程。返回应用后进入“自动签到设置”，勾选每天自动签到，配置签到时间和可选通知并保存。通知可单独测试。首页的“立即签到一次”会手动发起任务；验证码错误时会立即换图补试一次。“退出账号”会清除 Cookie、关闭自动签到和登录态刷新，通知配置继续保留。

部分手机的 WebView 会在密码已经完整填入后仍只显示 1 个圆点，这是网页控件的显示问题。请以 APK 顶部显示的实际字符数为准，不要直接在网页密码栏中连续输入；数量不对时点“重新输入密码”。需要核对内容时，可以先在系统密码输入框勾选“显示密码”，再点“填入网页”。

Android 的 WorkManager 会持久化每日签到、登录态刷新和可选的低电量检查任务，手机黑屏后仍可执行。部分手机熄屏后会暂时挂起 Wi-Fi；自动签到在提交之前遇到这类网络中断时，会按约 5、10、15 分钟的间隔等待网络并重试。验证码错误会在当前任务内立即换图补试一次；其他已经进入提交阶段的错误不会自动重试，避免消耗剩余机会或重复提交。省电、断网、关机等情况仍可能延迟运行。

低电量任务最短约每 15 分钟检查一次，因此提醒不保证恰好在达到阈值时发出。Bark 遇到超时、DNS、连接中断、限流或临时服务器错误时最多重试两次；网络状态不确定时可能收到重复通知。签到结果和测试通知中的 Bark、邮件会并行发送，任一渠道失败不会阻塞另一渠道。登录态刷新也依赖服务端愿意延长会话，因此不能保证永不需要重新登录。登录失效和低电量 Bark 都需要配置 Bark Key，普通网络故障不按登录失效处理。通知凭据保存在应用私有数据中，Android 备份已关闭。

### 退出后台后的自动签到

- 锁屏、黑屏或应用进程被系统正常回收：后台任务仍可运行；v1.0.4 已在真实手机上完成黑屏签到测试。
- 从最近任务列表划掉应用：通常不影响已经交给 WorkManager 的任务。
- 在系统设置中点“强行停止”：系统会停止应用的全部后台任务，重新打开一次应用后才会恢复。
- 使用系统“一键清理”或省电工具：部分品牌可能将其作为强行停止或限制后台运行处理。

华为等后台管理较严格的手机，建议在系统的应用启动管理中允许“自动启动、关联启动、后台活动”，并将本应用的电池优化设为“不允许优化”或同等选项。不同品牌和系统版本的菜单名称可能不同。

项目使用 Go 版相同的 `common_old.onnx` 与 `charsets_old.json` 模型，并通过 ONNX Runtime Android 执行本机 OCR。模型来自 `go-ddddocr` v1.0.1。APK 支持 Android 7.0 及以上的 ARM64 与 ARMv7 手机。

构建需要 JDK 17、Android SDK Platform 35 和 Android Gradle Plugin 8.13.2。用 Android Studio 打开仓库中的 `android` 目录并运行 `assembleDebug`，或执行：

```sh
cd android
./gradlew assembleDebug
```

生成文件为 `app/build/outputs/apk/debug/app-debug.apk`。Debug APK 已自动签名，可以直接安装；GitHub Release 之间若签名不同，升级需先卸载旧版，旧版数据也会被清除。
